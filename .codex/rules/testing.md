# 测试规范

## 当前基线

- 后端已有 7 个测试文件，集中在 router、middleware、日志、定时任务和代码生成。
- 前端没有测试框架或测试脚本；不要未经授权引入新的测试依赖。

## 后端

- 测试文件命名为 `*_test.go`，放在被测 package 附近；优先表驱动测试和 `t.Run`。
- 修改 Go 代码后在 `server/` 运行 `go test ./...`；至少运行被改 package 的测试。
- service 单测应隔离数据库、Redis、文件系统和时钟；无法隔离时明确测试前置条件，禁止连接真实生产基础设施。
- 修改代码生成模板时同步覆盖生成内容、Go 语法和前端样例契约；保留 `CODEGEN_SAMPLE_DIR` 的显式启用语义。
- 修复缺陷时尽量先补可复现测试，尤其关注认证权限、数据范围、定时任务重载和错误信息泄漏。

## 前端

- 修改前端后在 `web/` 至少运行 `pnpm lint` 和 `pnpm build`。
- 若任务明确引入测试框架，优先选择与 Vite 兼容的 Vitest，并为路由转换、store 和纯工具函数先补单测。
- 涉及登录、刷新 token、动态菜单、安装跳转或权限按钮时，补充手工验收路径并验证失败分支。
